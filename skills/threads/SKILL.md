# 线头

用户的个人待办看板。所有事情按「线头」（一个项目或一类事）分组，放在同一块六列看板上。用户在网页上拖卡片，你用 `xt` 命令读写同一份数据，网页会实时刷新。

只用 `xt` 操作，不要直接读写数据文件。下文的 `xt` 代表这份安装里的启动器。安装 skill 后，按末尾「本机调用」给出的绝对路径执行，可从任意工作目录使用。仅复制本文件时，请先按仓库 README 完成部署。

## 什么能主动做，什么要等用户开口

- **可以主动做**：已有卡片的状态和记录。开始一项工作时可以 `xt list` 看看有没有对应的卡片；有，就按下面的流程移动它、写进度。
- **只在用户明确要求时做**：新建卡片（`xt add`）、新建线头（`xt thread add`）、删除、归档、标完成。没有对应卡片时就不碰线头，也不要追问要不要加。

## 先看清楚

```bash
xt list                 # 未完成的卡片，按列分组；每行：#id 线头 标题 用时 截止 重要度
xt list --thread 官网   # 只看一个线头
xt show 12              # 一张卡片的全部内容和进度记录
xt thread list          # 有哪些线头
```

需要解析时加 `--json`。

## 六列，以及谁来移动

| 列 | 写法 | 含义 |
|---|---|---|
| 明天 | `明天` | 用户自己挪进来重新安排，**你不要往这里放** |
| 原始需求 | `原始需求` | 随手记下、还没想清楚的事（`xt add` 的默认列） |
| 整理后待执行 | `待执行` | 想清楚了、可以开工 |
| 执行中 | `执行中` | 正在做 |
| 检查中 | `检查中` | 做完了，等用户确认 |
| 完成 | `完成` | 用户确认过 |

你做事时的流程：

1. 开始做一张卡片 → `xt move <id> 执行中`
2. 有实际推进或卡住 → `xt log <id> "…"`（什么算推进见下文「记录进度」）
3. 做完 → `xt move <id> 检查中`，并 log 一句做成了什么、怎么验证的
4. **不要自己 `xt done`**，除非用户明确说"标完成"。完成由用户确认。

## 记新事情（用户明确要求时）

```bash
xt add "给房东打电话" --thread 生活
xt add "修登录页报错" --thread 官网 --column 待执行 --due 15:00 --est 1.5h \
  --desc "Safari 上点登录后白屏" --when "Safari / Chrome 都能登录"
```

- 标题写成一句短的动作，看一眼就知道要做什么。
- 线头：先 `xt thread list`，选名字对得上的。都对不上时问用户放哪个线头；只有用户说了要新建，才 `xt thread add <名字>`。
- 用户只是随口一提 → 放默认的原始需求。用户说清了要做什么、怎样算做完 → 放 `待执行`，并写 `--when`。
- `--due` 和 `--est` 只在用户给了，或能明确推断时才写，别编。没写截止时间时，按当天 23:30 计算重要度。
- 时间写法：`15:00`（今天）、`11-07 15:00`、`2026-11-07`（当天 23:30）。用时：`30m`、`1h`、`1.5h`。

## 记录进度

进度记的是这件事实际推进到了哪里，给用户扫一眼就知道"还差多少、要不要我出手"。它不是操作日志，过程细节留在 git 和对话记录里。

判断标准：用户看到这条，对"还差多少、要不要出手"的判断会变吗？会就记，不会就不记。

**记：**
- 离结束条件近了一步（完成了其中一项）
- 找到了关键原因，或定下了方案
- 卡住了，需要用户决定或提供东西
- 方向或范围变了
- 做完移到检查中时：做成了什么、怎么验证的

**不记：** 读了哪些文件、跑了什么命令、改了哪个文件、测试跑了一遍、开始做了（移到执行中已经说明了）。

同一个推进还在细化时，改上一条记录（`xt log-edit`），不要另起一条。一张卡片通常只有三到五条记录。

```bash
xt log 12 "原因是 cookie 的 SameSite 设置，已改好，等部署" --author claude
xt show 12                                  # 查记录 id
xt log-edit 12 3 "原因是 cookie 的 SameSite=Strict，改成 Lax 后 Safari 能登录，等部署"
```

- `--author` 写你自己：Claude 写 `claude`，Codex 写 `codex`。也可以先 `export XT_AUTHOR=claude`。
- 一条一句话，不贴日志、不贴代码。

## 其他命令

```bash
xt edit 12 --title … --desc … --when … --due 18:00 --est 1h --thread 论文
xt edit 12 --no-due      # 清掉截止时间
xt open                  # 在浏览器打开看板（服务器没开会自动在后台启动）
xt help                  # 完整用法
```

`xt rm`（删卡片）、`xt archive`（归档完成列）、`xt thread rm` 只在用户明确要求时使用。

## 回复用户时

改完后用一两句说明改了哪张卡片及其所在列。

面向用户提到卡片时，编号与任务名称一起出现。首次提及时注明所属线头，例如“线头「官网」的 #1『更新首页』”。后续优先使用容易理解的任务名称，编号用于辅助定位。
